## 修复与核查

- `patch-fast-mode.js`：匹配完整 `fast_mode` 字段、新版 `readServiceTier` 账户回调及界面 `serviceTierAccess` 权限入口。实测发现仅放行后端仍不会显示快速模式，已补齐界面判断，保留加载状态和服务端显式禁用；避免误改首页 banner 的 ChatGPT 产品判断，认证扩展增加括号以保留布尔优先级。
- `patch-model-catalog-filter.js`：兼容 allowlist 后新增的 API-key 访问计划分支，保留隐藏模型与前置拒绝条件；排除只调用过滤函数的资源块。
- `patch-thread-file-manager-action.js`：兼容远程连接状态抽为 selector 后的侧栏结构，保留远程连接排除条件。
- `patch-model-picker-submenu.js`：识别新版原生点击切换模型列表，保留上游组件。
- `patch-browser-auth.js`：逐份检查四个真实浏览器运行时，确认新版请求头直接来自配置；保留旧版身份失败降级补丁。
- `build-current.js`：修复 Windows 新版 Node 无法直接执行 `npm.cmd` 的 `EINVAL`。
- `patch-updater.js`：修复 `--check` 仍写文件的问题，输出前重新解析 JavaScript。
- `fetch-msstore.js`、`sync-upstream.js`、`check-update.js`：下载链接按摘要匹配，空结果重试，x64 包按数值版本排序，检测失败明确返回错误；CLI 先按架构筛选再取链接。

同时复核并保留历史修复：外置 `plugins/cua_node` 覆盖、便携 Owl 启动器、ASAR 完整性哈希、同包 CLI、图像生成认证、实时语音入口、Git 输出上限、worker 内存限制、diff 上限及 CDP 截图保护。工作区根目录传递、归档删除和 Sentry 防膨胀由新版上游原生实现。

浏览器测试复制配置时需将内置市场路径改为新 `CODEX_HOME` 下的规范绝对路径。沿用原目录或 Windows 8.3 短路径会被新版内置市场来源校验拒绝；修正测试环境路径后，插件加载与浏览器完整流程通过。

原配置中的外部 MCP 并未全部验收：独立 app-server 启动时，`chrome-devtools` 报命令未找到，`fast-context` 报连接关闭，`scys-mcp` 要求 OAuth 登录。这些集成仍需分别检查启动配置或完成登录，不能计入通过项。内置浏览器的上述实测不依赖 `chrome-devtools`。

桌面验证使用独立 `CODEX_HOME` 和用户数据目录，没有替换当前运行中的旧版。临时指令限制了测试范围，两个测试目录中的登录认证副本 `auth.json` 已移除。工具策略拒绝删除临时 `config.toml`（仅返回 `blocked by policy`），因此含外部 MCP 配置的副本仍留在 `%TEMP%/codex-functional-desktop-UXzSao/codex-home` 和 `%TEMP%/codex-functional-server-CoFmHV/codex-home`。当前用户配置和历史会话未由本次升级改写。
