# 上游 26.1120 补丁兼容与自动构建修复（2026-11-25）

## 失败现象

GitHub Actions 运行 `45567709704`（Sync Upstream & Patch #43）在 `Patch` 步骤失败：

- `build-mac (arm64)`、`build-windows`、`build-linux (arm64)` 退出码 1；另两个作业随后被取消。
- 上游已更新为 macOS `26.1120.50957`（build 30866）、Windows x64 `26.1120.6357.0`，但仓库补丁仍按 `26.1111` 的前端结构定位。

## 原因

1. 前端功能 chunk 移入 `webview/assets/async/<id>.<hash>.js`（9,589 个文件），`assets` 根目录仍保留少量入口 chunk（如 `index.html` 直接加载的 `assets/348410.f0081c7d18.js`）。只枚举根目录或依赖 `index-*`、`app-main-*`、`app-initial-*`、`app-primary-*`、`data-controls-*` 等文件名的补丁因此跳过，其中三个脚本直接报错。
2. 中文语言目录外置为 gzip JSON：`assets/locales/keys.<group>.json.codex-gzip` 与 `<lang>.keys.<group>.<hash>.json.codex-gzip`，原 `zh-CN` JS 分片只剩一个取这两个文件的加载器。
3. app-server 参数模块同时被复制进 `app-server-host.js` 和 `early-bootstrap-824-*.js`，图片生成认证补丁断言“只命中一个 bundle”而失败。
4. Browser Use 不再要求 caller identity，`codex_browser_use_agent_request_header` 闸门被移除；实现移入 `browser-service-core.mjs`，`browser-service.mjs` 变成动态导入核心的瘦启动器。
5. Windows Browser Use 运行时目录布局变化：部分目录只剩客户端文件，服务协议改由 `browser-service-core.mjs` 承载。

## 修复范围

- `patch-reasoning-effort-labels.js`：按消息 ID 回写 `zh-CN` gzip 语言目录；keys 组哈希不匹配时回退到包含推理强度消息的 keys 目录；写入前做 gunzip + JSON 回读校验。旧 JS 语言包路径保留。
- `patch-image-generation-auth.js`：同一平台的多个 app-server 参数 bundle 全部打补丁，runtime 文件按 `buildDir` 只同步一次；零命中仍明确报错。
- `patch-browser-auth.js`：同时发现 `browser-service.mjs` 与 `browser-service-core.mjs`；原生核心（忽略空白差异）标记为 `native`，只有确认动态导入 `browser-service-core.mjs` 的瘦启动器才标记为 `skip`；其他无闸门或未知结构仍然失败。
- `repair-browser-runtime.js`：按各目录实际存在的客户端/启动器/核心/WASM 逐项同步；协议校验解析到真正实现核心；入口目录为空时预检失败且不写入。目标目录已存在但缺少上游新增产物（如拆分后的 `browser-service-core.mjs`）时按新增安装，回滚时删除新增文件；服务文件被改名时明确报错。
- `patch-i18n.js`：26.1120 的 3 个 async chunk 确实包含 `enable_i18n` 闸门，其中一个默认 `!1`；补丁将其替换为带 `codex-i18n-enabled` 标记的 `!0`，重复执行按标记报告已启用，不再与“上游移除闸门”混淆。
- 递归按内容定位：`patch-fast-mode.js`、`patch-realtime-voice-auth.js`、`patch-model-catalog-filter.js`、`patch-thread-copy-markdown.js`。模型目录补丁在预筛命中却无法改写的候选上明确失败，不再静默跳过。
- 原生能力识别：
  - `patch-archive-delete.js` 识别 26.1120 的 `delete-archived-conversations` / `deleteAllArchivedConversations` / `deleteWithTitle` 链路，不再注入旧路由；非原生平台只要缺少路由或按钮注入中的任一层，就以退出码 1 结束，不再静默跳过。
  - `patch-thread-copy-markdown.js` 识别复制处理器原生强制加载完整历史并解析父会话的形态，只在动作本体上判断，避免被外层模块包装函数误判。

- `patch-composer-workspace-root.js`：上游改用 `readThreadWorkspaceRoots` / `runtimeWorkspaceRoots` 解析工作目录，旧片段不再存在。
